# MaterialBook — Progress & Agent Handoff

> **EVERY AGENT: read this file FIRST, before touching any code.** It is the single source of truth for what is done, what is next, and who owns what. Then read `docs/ARCHITECTURE.md` (decisions/standards). Do not re-derive decisions from chat history.

## Protocol (mandatory)

1. **Claim before you work.** Pick one `TODO` task whose dependencies are `DONE`. Change its status to `IN_PROGRESS`, put your agent label + UTC time in the *Owner* column. Save the file *before* writing code.
2. **Stay in your lane.** Only create/edit files listed in the task's *Files* column. Never edit another in-progress task's files. Shared files (`pom.xml`, `docker-compose.yml`, `package.json`, `router.tsx`) are edited by appending only, and you must re-read them immediately before editing.
3. **No unnecessary code.** Before creating a class/component/util, grep for an existing one. Reuse `common/` and `components/common/`. No speculative features, no unused DTOs, no copy-paste of the proposal's illustrative snippets. Build only what the task's *Done when* says.
4. **Finish properly.** Run the task's verification (tests/build). Set status `DONE`, fill *Verified by*, and add one line to the Session Log (what was built, what is deliberately left, gotchas). If you stop midway, set `PARTIAL` and write exactly where you stopped.
5. **Record decisions.** Any deviation from `ARCHITECTURE.md` goes in the Decision Log below *and* in ARCHITECTURE.md. Never silently diverge.
6. **Never** introduce a dependency that is not permissive-licensed (see ARCHITECTURE §6). Never commit secrets.

Status values: `TODO` · `IN_PROGRESS` · `PARTIAL` · `DONE` · `BLOCKED`

## Decision Log (deviations from the original proposal)

| # | Decision | Reason |
|---|----------|--------|
| D1 | PDF via **Apache PDFBox only** + embedded **Noto Sans** (SIL OFL). No iText/JasperReports/Flying Saucer. | License-free (Apache-2.0/OFL); iText is AGPL. PDF base-14 fonts lack `₹`, so a Unicode font must be embedded. |
| D2 | Use `spring-boot-starter-oauth2-resource-server` as the **only** JWT mechanism; drop custom `JwtAuthenticationFilter`. | Less code, battle-tested validation. |
| D3 | Added `stock_balances` (locked row per product) + signed `stock_movements.quantity_delta`. | Cheap concurrency-safe locking; O(1) stock reads; DB CHECK forbids negative stock. |
| D4 | Removed `material_transactions.total_quantity`; `items.amount` is a generated column. | Mixed units make qty sum meaningless; prevents amount drift. |
| D5 | Added `party_payments` table. | Supplier ledger in the proposal had no way to record payments. |
| D6 | `material_attachments` → generic `attachments` with 3 real nullable FKs + `num_nonnulls = 1` CHECK. | Expense/payment attachments were required but unmodelled; keeps referential integrity. |
| D7 | Removed `NEGATIVE_STOCK_ALLOWED` setting; removed users.status `LOCKED` (use `locked_until`). | Rule 5 is absolute; lockout is time-based. |
| D8 | `refresh_tokens` gets `family_id` for reuse detection; token hash is SHA-256 hex. | Stolen-token replay protection. |
| D9 | `audit_logs` append-only via trigger; `document_sequences` PK is (type, year) and numbering uses `next_document_number()` SQL function. | Tamper resistance; atomic duplicate-free numbers. |
| D10 | Added permissions: `INVENTORY.*`, `EMPLOYEE.*`, `PARTY.*` (replaces `SUPPLIER.*`), `PAYMENT.*`, `EXPENSE_CATEGORY.MANAGE`, `SETTINGS.MANAGE`. | Proposal's list did not cover parties-as-clients, payments, employees. |
| D11 | Ledger sign convention is `opening + ΣOUT − ΣIN − ΣRECEIVED + ΣPAID` (positive = party owes us). The comment above `party_payments` in V1 says `+RECEIVED − PAID`, which is business-wrong (a client paying us must reduce what they owe; paying a supplier must reduce what we owe, i.e. raise a negative balance toward 0). V1 is immutable, so only its comment text differs; code and ARCHITECTURE §3 use the corrected formula. | Business meaning: client owes 1000, pays 400 -> 600; supplier we owe 1000 (-1000), we pay 400 -> -600. |
| D12 | Material edit uses `StockService.replace()` (atomic reversal + repost, stock checked on the NET effect per product), not `reverse()` then `post()`. | E2E found that reverse-then-post wrongly refused raising an IN after a partial dispatch (net +7.5 was seen as −5). Ledger stays append-only. |
| D13 | Dashboard money data has its own permission `DASHBOARD.FINANCIAL` (V8); `GET /reports/dashboard` omits sections the caller may not see (and skips their SQL). The VIEWER system role is reduced to DASHBOARD/MATERIAL_IN/MATERIAL_OUT/INVENTORY/PRODUCT view, overriding any manual edits to it. | Hiding in the UI is not security; viewers must not see expenses, receivable/payable or the transaction list. |
| D14 | Employee salary is monthly with dated revisions (V9 `employee_salary_revisions`, source of truth; `employees.monthly_salary` mirrors today's value, reads resolve by date so future-dated increments need no scheduler; "today" = Asia/Kolkata). Old weekly figures were only renamed, NOT converted. Salary payment type WEEKLY -> MONTHLY (rows migrated); salary expenses store no period/payment mode/voucher; electricity expenses store hours/days (`usage_quantity`) instead of units x rate, old columns kept unused. | Owner's confirmed requirements for the expense/employee rework. |
| D15 | Material IN/OUT lines carry an optional entry `unit` (TON\|KG\|PIECE, default TON in the UI). The server converts `quantity` to the PRODUCT's unit (1 TON = 1000 KG, scale 3, HALF_UP; result 0.000 or a PIECE<->weight mix -> 422 on `items[i].quantity`/`.unit`); stored quantity, stock, totals, audit, PDFs and reports stay in the product unit, no schema change. Rate is always per product unit; amount = stored quantity x rate. | Users buy/dispatch in TON or KG while stock must stay in one unit per product; converting only the quantity avoids rate rounding. |
| D16 | ONE application image: the Spring Boot jar serves the compiled SPA (`classpath:/static/`, SPA fallback, cache rules) and carries every security header/TLS option nginx had; the nginx container, `nginx/` and `backend/Dockerfile` are gone (root `Dockerfile`, services `app` + `postgres`). Optional built-in HTTPS via Spring Boot PEM env vars; default plain HTTP behind the operator's proxy. | User request: run the application as a docker image, frontend compiled files inside the backend. Edge rate limiting (nginx zones) and the :80 redirect are no longer provided (docs/SECURITY_REVIEW.md section 7). |
